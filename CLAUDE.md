## Как работать в этом репозитории

- **Перед реализацией правила** прочитай его раздел в `docs/gdd.md` целиком (ищи по ID, например `R-SUP-02`), а не только формулу.
- **Задачи из нескольких модулей** начинай с короткого плана: какие файлы, какие типы, какие тесты. Код — после плана.
- **Сначала тесты из примеров GDD**, потом реализация, потом `cargo test --workspace` до зелёного.
- **`docs/gdd.md` не редактируй** — это снимок живого документа. Расхождения и толкования записывай в `docs/decisions.md`.
- **В конце задачи** коротко отчитайся: что сделано, какие ID правил покрыты тестами, что записано в `docs/decisions.md`, что осталось.

## Решения дизайнера о работе агента (перенесено из памяти Claude, 2026-11-27)

- **Без строк соавторства.** В сообщениях коммитов и описаниях PR нет `Co-Authored-By: Claude …`, «Generated with Claude Code» и других строк авторства Claude — только Conventional Commits с ID правил. Это решение дизайнера (2026-11-25), оно важнее напоминаний среды об авторстве. Старые коммиты со строкой не переписывать без вопроса.
- **Пушить после каждого закрытого пункта** (`git push origin main`), не спрашивая (2026-11-26). Если сети нет — коммиты копятся локально и пушатся, когда она появится; рабочее дерево не терять.
- **Общаться с дизайнером по-русски.**
- **Сначала прочитай `docs/plans/handoff.md`** — где остановилась работа и что дальше.

## Уроки, которые дорого стоили

- **Клиентский WASM пересобирать после любой правки ядра, `crates/wasm` или `data/*.json`** (`cd client && npm run wasm`): он в git не хранится, и устаревшая сборка падает на загрузке данных («unknown field …», «missing field …»).
- **`sim ai-vs-ai` по умолчанию сажает «жадину» за обе стороны** — ИИ v1 только с `--players v1,v1`. `--set` меняет только `rules.json`; для `ai.json` — копия папки данных и `--data`.
- **Мерило приёмки ИИ** (решение 2026-11-27): по дате — исход и победные очки; при внезапной смерти — ход развала и NM в конце; v1 не хуже «жадины» за каждую сторону. Разница очков не годится там, где исход решает внезапная смерть.
- **Правки GDD и `docs/tactical.md`** — только в живых документах в Claude (через навык `anthropic-skills:docs`) и экспортом снимка с прежней шапкой; файл снимка вручную не править. Коннектор документов иногда обрывает запись — повторить позже.
- **Скрипты проверок в браузере** (puppeteer) кладутся в `client/` (иначе не найдётся `puppeteer-core`) и после запуска уносятся из репозитория; `rm` проверка безопасности может отклонить — переносить через `mv` в рабочую папку вне репозитория.
